## Suggested patch for item 6 (for Bay; not applied)
```python
def _write_atomic(path: Path, text: str) -> None:
    tmp = path.with_name(f".{path.name}.{os.getpid()}.{uuid.uuid4().hex[:8]}.tmp")
    try:
        with open(tmp, "w", encoding="utf-8") as f:
            f.write(text)
            f.flush()
            try:
                os.fsync(f.fileno())
            except OSError:
                pass
        for attempt in range(20):
            try:
                os.replace(tmp, path)
                return
            except PermissionError:  # Windows: a reader has job.json open for a moment
                if attempt == 19:
                    raise
                time.sleep(0.01)
    finally:
        tmp.unlink(missing_ok=True)  # no-op after a successful replace
```
Optionally, fsync the directory on POSIX after `os.replace`, so the rename itself survives a crash. A test for the write-failure path would pin the cleanup down, e.g. monkeypatch `open`/`write` to raise and assert that the folder holds only `job.json`.

**Other behaviour changes (notes, not failures)**
- **Save cost:** each save now costs about **0.45 ms instead of 0.10 ms** on the box (`5-save-cost.txt`, 1,000 saves). The race harness's save rate fell from about 40k to about 9.6k per run. That's fine for progress-rate saves, but on slow disks (HDD, network folders) every save now waits for 2 fsyncs.
- **Mode under a strict umask:** "never 0600" holds under umask 022. A new job.json still follows the umask, so under umask 077 it's 0600, the same as the old `write_text`.
- **New inode and owner:** job.json gets a new inode on every save, owned by whoever saves it; only the mode is copied over. A symlinked job.json would be replaced by a regular file, whereas the old code wrote through the link. Neither layout is used by the app.
- **Windows:** a save can raise `PermissionError` after about 0.19 s if a reader holds job.json open throughout; this is unchanged from 0d249f2. CI's Windows clean test passed.
