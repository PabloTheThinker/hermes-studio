## v0.6.2: what a tool call may read, write and fetch

This patch keeps the v0.6.1 editor, clips pipeline and chat plugin, and tightens what the engine (and the Hermes Agent plugin in front of it) lets a caller read, write and fetch. Package, desktop app and plugin are aligned at 0.6.2.

### Files

- Local sources go through `local_source()`: an existing video/audio file (PNG/JPEG/WebP for photo tools) under your home folder, `/mnt`, `/media`, `/srv`, the library, or `HERMES_STUDIO_MEDIA_ROOTS`.
- Outputs (`edit --out`, `photo --out`, `run --out/--work`, `captions --out`, `transcribe --work`, `list --out`) must sit inside `~/.hermes/clips` or `HERMES_STUDIO_OUT_ROOTS`. Existing files are never overwritten; default names get a `-2`, `-3`… suffix.
- `duplicate_file` checks its source the same way and creates the copy exclusively. Drop and restore only move clips that already sit in `~/.hermes/clips`.

### Links

- Media links must be public http(s). The host is resolved and loopback, private, link-local (169.254.169.254), CGNAT (100.64/10), multicast, reserved and unspecified addresses, in IPv4, IPv6 and v4-mapped form, are refused.
- yt-dlp now runs through `hermes_studio.safe_fetch`. Every connection is checked after DNS resolution, so every redirect hop is covered. FFmpeg children (live HLS) go through a loopback proxy that checks each request the same way.

### Hermes Agent plugin

- The engine gets a minimal environment: `PATH`, `HOME`, `LANG`, `TMPDIR`, `PYTHONPATH` when set, and `HERMES_STUDIO_*`.
- Caption cues and the desk log live in `<hermes home>/plugin-data/hermes-studio/`, per profile.
- The desk tool no longer takes a `host` argument; it always binds 127.0.0.1.
- The plugin refuses an engine older than v0.6.2. Its install hint points at this tag: `uv tool install git+https://github.com/PabloTheThinker/hermes-studio@v0.6.2`.

It runs on your computer only. Nothing is uploaded or posted.
